# Undernote Website Revision Brief
## Full positioning, copy and UX rewrite for the current website

**Status:** Implementation brief  
**Brand:** Undernote  
**Tagline:** **A world in tune with you.**  
**Primary objective:** Make the website immediately understandable and compelling to a broad consumer audience, while keeping the sophisticated context architecture underneath the surface.

---

# 1. What this revision is trying to achieve

The current website contains most of the right product mechanics, but the visible product language is too narrow, too technical and too shaped around one prototype persona.

The revised website should communicate one simple consumer benefit:

> **Undernote makes more of the world feel like it was meant for you.**

It does this by bringing in what the user has already taught AI, building a private understanding of what matters to them, and then using that understanding to surface things that feel unusually well chosen for them.

The site should make a visitor understand three things within seconds:

1. **Undernote already has a fast way to understand me** — I can bring in what ChatGPT, Claude or Gemini already knows.
2. **That understanding immediately does something useful** — it starts finding films, books, articles, news, places, events, trips, products and opportunities that fit me unusually well.
3. **It becomes even more useful when other people are involved** — for a shared decision such as going out, each person can contribute only the context relevant to that decision.

The sophisticated machinery — context tokens, ontology, weighting, provenance, permissions, expiry, context merging and ranking — should power the product, not dominate the product language.

# 4. Important positioning corrections

## 4.1 Undernote is not a product for “quiet people”

The current website overuses ideas such as quiet quality, secluded retreats, acoustic purity, intimate stages, calm, quiet boundaries and quiet discovery.

These are valid preferences for the current demo persona, but they must not become the personality of the entire brand.

A user’s perfectly tuned Undernote might surface:

- a techno festival
- a packed football match
- a huge gaming laptop
- a loud family restaurant
- an adventure trip
- a mainstream blockbuster

**Undernote itself can be quiet. The user’s world does not have to be.**

Keep the interface restrained; broaden the examples and imagery.

## 4.2 Do not make privacy the acquisition proposition

Privacy and user ownership are important trust foundations, but the primary reason to try Undernote is the benefit:

> **The world fits better when it understands you.**

Privacy should reassure the user after the value proposition is understood.

## 4.3 Remove “zero algorithms”

This claim is inaccurate in spirit because Undernote necessarily uses algorithms for ranking and matching.

Replace with language such as:

- **No ad-tracking profile**
- **No sponsored ranking**
- **No selling your attention**
- **Your context is used for you, not advertisers**

## 4.4 Be precise with architecture claims

Do not make claims such as “100% on-device,” “100% private matching,” “zero server retention,” or “completely local” unless they are literally true of the production architecture.

Safe language:

> **Your context is yours. You can see it, change it, export it or delete it.**

If local storage is truly implemented:

> **Stored locally by default.**

# 25. Interaction principles

## 25.1 Show the result before the machinery

Never make the user understand the context model before they see value.

## 25.2 Explain recommendations in plain language

Every recommendation should be able to answer:

- Why me?
- Why now?
- What changed?
- What can I do?

These do not need to appear as four literal labels on every card.

## 25.3 Avoid confidence theatre

Do not invent or prominently display 94%, 98%, 99% match scores.

## 25.4 Ask questions only when value is visible

Good:

> **I can make these restaurant picks better if I know whether outdoor seating matters tonight.**

Bad:

> Complete your profile: 72%.

## 25.5 Non-users must be able to participate in Together

A recipient of an invite should be able to:

1. open the link
2. see what decision they are joining
3. contribute only the relevant preferences
4. see the result

before being asked to create an Undernote account.

After value:

> **Want Undernote to remember these preferences and start finding things for you too?**

This is an important acquisition loop.

# 31. Acceptance criteria

The rewrite is successful if a first-time visitor can answer these questions after 20–30 seconds:

### What is Undernote?

> A product that uses what it knows about me to make more of the world feel relevant and well chosen for me.

### How does it know me?

> I can bring in what I already taught ChatGPT, Claude or Gemini. I can also add things myself.

### What does it actually do?

> It finds things for me — films, books, articles, news, places, events, travel opportunities, products and other useful discoveries — and it can keep watching things I care about.

### Why would I return?

> Because it occasionally finds something unusually relevant without me having to search for it.

### Why would I invite someone?

> Because Undernote can help us choose somewhere to go by combining only the preferences that matter for that decision.

### Why should I trust it?

> I can see, change, export and delete the context it uses, and recommendations are not sponsored.

If the website makes these six answers obvious without teaching the visitor about ontology, horizons, sovereign architecture or context graphs, the revision has achieved its goal.

# 32. Final product principle
